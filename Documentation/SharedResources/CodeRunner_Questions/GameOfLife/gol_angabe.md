# GameOfLife

Implement *Conway's Game of Life*.

## Introduction

[Conway's Game of Life (GoL)](https://en.wikipedia.org/wiki/Conway%27s_Game_of_Life) is a cellular automaton with [simple rules](https://www.youtube.com/watch?v=jvSp6VHt_Pc) that displays surprisingly [complex behavior](https://www.youtube.com/watch?v=C2vgICfQawE).

The basic idea is an infinite rectangular grid of (square) **cells** that can be **live** or **dead**.
The grid of cells **evolves** step by step. A live cell can die of overpopulation if it has too many neighbors or of underpopulation when it has too few neighbors. A live cell lives and dead cells can even come to life when they have just the right amount of neighbors. The **neighborhood** of a cell is the 8-connected neighborhood (N, NE, E, SE, S, SW, W, NW).

The exact rules are:

1. Any live cell with fewer than two live neighbors dies, as if by underpopulation.
2. Any live cell with two or three live neighbors lives on to the next generation.
3. Any live cell with more than three live neighbors dies, as if by overpopulation.
4. Any dead cell with exactly three live neighbors becomes a live cell, as if by reproduction.


Although a simple model, Conway's Game of Life can display complex patterns. Interesting features include "still lives",  "oscillators", "gliders" even "space ships", "ray guns" and many more which are fun to explore.

## Assignment 

We play GoL on a 32-by-32 grid. The grid is represented by a two dimensional array. The x-axes runs from top to bottom, the y-axes from left to right. The top leftmost cell has coordinate (0, 0). The initial configuration is evolution step 0. For cells on the border only existing neighbors are considered.

Your program

- reads the coordinate of the live cells of the initial configuration (zero or negative x-coordinate ends input; assume correct input - no input validation necessary)
- starts the evolution 
	- displays the grid in current state
	- reads the number of evolution steps to perform (zero, or negative ends program)
