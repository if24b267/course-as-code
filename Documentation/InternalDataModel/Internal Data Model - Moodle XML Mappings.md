# Internal Data Model - Moodle XML Mappings

General thing to consider: Some tags aren't explcitily saved in the internal data model as the values of these tags can be inferred or aren't relevant, e.g.:  
- Each section has a `<number>` field that determines the order, in which the sections are arranged. The value of this field is NOT explicitly saved in the data model as all sections are saved in an ordered list in the `Course` class and the order of the sections can be inferred from their position in the list.
- Each section has an ID and a number. The ID is a thing only needed by moodle and thus isn't saved in the interal data model. It is the job of the writer to generate appropriate IDs.

### /course/course.xml
Most of the tags in this file are represented by the `Course` class, though their names might differ.

A selection of a few mappings that may be especially hard to infer:  
- `<newsitems>` -> `NumberOfAnnouncementsToDisplay`
- some tags like `<marker>` aren't represented in the internal data model as their purpose is still unclear

### /course/enrolments.xml

- `<enrol id="">`: Each available enrolment method is represented by one instance of the class `EnrolmentMethod`
- `<enrol>`: there are multiple classes that inherit from `EnrolmentMethod` (`Enrolments/ManualEnrolment`, `Enrolments/SelfEnrolment`, ...) - their name defines the anrolment method
- `<status>`: represented by the `Enabled` boolean in `EnrolmentMethod`
- `<name>`: represented by CustomName in `Enrolments/SelfEnrolment`
- `<enrolperiod>`: represented by `EnrolmentDuration` in `Enrolments/*`
- `<enrolstartdate>`: represented by `EnrolmentStartDate` in `Enrolments/SelfEnrolment`
- `<enrolenddate>`: represented by `EnrolmentEndDate` in `Enrolments/SelfEnrolment`
- `<expirynotify>`: represented by `NotifyEnroller` and `NotifyStudent` in `Enrolments/*`
- `<expirythreshold>`: represented by `NotifyThreshold` in `Enrolments/*`
- `<notifyall>`: represented by `NotifyEnroller` and `NotifyStudent` in `Enrolments/*`
- `<password>`: represented by `Password` in `Enrolments/*`
- `<cost>`: only applicable to enrolment methods not yet implemented in the internal data model
- `<currency>`: only applicable to enrolment methods not yet implemented in the internal data model
- `<roleid>`: represented by `DefaultRole` in `EnrolmentMethod`
- `<customint1>`: these fields are probably used to save `SendWelcomeMessage` and `WelcomeMessage` in `Enrolments/*`
- `<timecreated>`: represented by `TimeCreated` in `EnrolmentMethod`
- `<timemodified>`: represented by `TimeModified` in `EnrolmentMethod`

#### User Enrolments
The User-Enrolment-Mappings are represented by the User Class in the data model.  
Each User has an EnrolmentMethod, EnrolmentStartDate, EnrolmentEndDate and EnrolmentStatus which correspond to the XML data.

## /course/inforef.xml
This file is not represented in the internal data model as it contains merely references to components of the course.  
Must be generated by the writers on the basis of the internal data model

## /course/roles.mxl
This file maps the roles that are available in the course (defined in roles.xml) to specific users.  
This is represented in the interal data model in the User class. Eacher user has a `Role` and a `RoleChange` property.  
All remaining tags of this file can be inferred from the data model or aren't saved explicitly.

## moodle_backup.xml
Most tags in this file are represented by properties in the `BackupMetadata` class, though they might have slightly different names.  

A few special cases:
- `<moodle_version>`, `<moodle_release>`, `<backup_version>` and `<backup_release>` are all mapped to the single `MoodleVersion` property as their values do not differ or can be inferred from another
- all `<original_*>` tags aren't explicitly represented in the data mdoel as these values can be inferred from the `Course` class
- the data inside the `<contents>` tag is not explicitly stored in the data model as this just lists all the activities and sections of the course which can be inferred from the corresponding classes in the internal data mdoel
- the `<settings>` are saved in the nested class `BackupSettings` of `BackupMetadata`

## gradebook.xml
not yet implemented as the first version of the prototype won't have gradebook support  

## roles.xml
Most tags in this file are represented by the `Role` class in the internal data model  

- `<nameincourse>` -> `LocalName`
- `<sortorder>` is not explicitly saved as it's not clear yet what this tag does - probably can be inferred from the data model anyways and doesn't have to be saved explicitly

## files.xml
A file is a type of activity. Most of the tags in this file are represented by the `Activites/Resources/MoodleFile` class and its' parent class `Activities/Activity`  

- some tags aren't yet represented by the internal data model as their purpose is unclear
- some tags aren't explicitly saved as they can be inferred from other fields, e.g. `<filesize>` and `<mimetype>` aren't explcitily saved as these values can be inferred by analyzing the file specified in `FilePath`
